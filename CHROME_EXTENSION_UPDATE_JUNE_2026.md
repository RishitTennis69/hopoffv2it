# Chrome Extension Update Brief: HopOff Changes

This update is for the Chrome extension version of HopOff. Keep the original extension prompt/design as the baseline, then layer these changes on top where they apply to browser behavior.

## Onboarding Flow

Rework onboarding into this order:

1. Goals
2. Overlay messages
3. Redirect destination
4. Videos
5. Websites/apps to limit
6. Permissions

Remove the older combined goals screen that asks for goals, overlay copy, and after-commit behavior all at once.

### Goals

Ask only for the user's weekly goals. This is mandatory. The user cannot continue with an empty goals field.

### Overlay Messages

Ask whether HopOff should write the overlay message automatically or whether the user wants to write their own.

If the user chooses custom messages, show a multiline field where each line is one possible overlay message. This field is mandatory only when custom messages are enabled. During an intervention, randomly choose one custom line.

### Redirect Destination

Ask: "Where should we send you after HopOff blocks a distracting site?"

For Chrome, recommended destinations can be:

- HopOff dashboard
- A user-provided URL
- A productivity web app, such as Google Docs, Calendar, Linear, Slack web, or a running/training site

Do not claim strong AI app detection unless it is actually implemented. If goal-based suggestions exist, phrase them as suggestions and require user approval.

## Session Limits

When the user creates a limit group, explicitly ask whether they want sessions.

If sessions are on, split the daily allowance into session chunks. Example: a 60 minute daily limit with 3 sessions interrupts every 20 minutes.

If sessions are off, use one normal daily limit.

Show a dashboard breakdown:

- sessions left today
- minutes left today
- session size

## Lock In

Move Lock In into its own main tab/page. Do not place the primary Lock In controls on the Progress dashboard.

The Lock In page should include:

- quick buttons, such as 30, 60, and 90 minutes
- a custom duration input
- presets for Morning, Work / school, and Night
- a custom time window
- a visual day timeline showing which hours are blocked

For a Chrome extension, Lock In blocks the configured distracting sites even if the user is under their normal daily limit.

## Shorts/Reels

Remove YouTube Shorts and Instagram Reels as separate selectable targets for now.

Treat browser YouTube as YouTube and browser Instagram as Instagram. Do not make product claims that HopOff can reliably block Shorts or Reels separately unless the extension implements robust URL/page-state detection and it has been tested.

## Intervention Overlay

Use the "message first, then video" flow:

1. Show the user's custom/autogenerated message first.
2. Fade smoothly into the video after a short pause, around 3.5 seconds.
3. Make the video as large as possible without hiding the action area.
4. Do not unlock the commit action until the full video has completed.
5. Do not let the user pause, seek, or skip the video.

If the embedded video provider cannot reliably report completion, use a controlled player implementation or a known-duration local/video-hosted asset. Do not unlock from a simple timer if the user can pause playback.

## Progress Dashboard

Keep Progress focused on progress, not Lock In controls.

Show today's tracked time separately from weekly or average time so users do not compare an average to their device's "today" number and think it is broken.

Show session state clearly when session limits are enabled.

## Removed Integrations

Remove Notion, Apple Notes, and Apple Reminders integration UI for now.

Goal redirects can still point to a user-approved website or app-like URL, but do not present these as built-in integrations.

## Permissions Behavior

When a permission is granted, detect it as soon as the user returns to the extension/app. On web/Chrome, this means listening for focus/visibility changes and rechecking the permission state.

Do not promise that the browser or operating system can automatically close a settings page and return to HopOff unless that exact platform API exists.
